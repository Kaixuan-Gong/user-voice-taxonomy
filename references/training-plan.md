# Laya 与中文向量模型训练方案

## 1. 目标与原则

本方案用于在标签体系稳定后，利用真实业务金标完成一次模型升级。训练不是每批数据的固定步骤；完成本次训练、验收并发布 checkpoint 后，日常任务只执行推理、拒识、统计与漂移监控。

训练分两条独立线路：

1. **Laya 分类训练**：学习业务标签之间的判定边界，提高三级标签路径准确率，并通过温度校准让输出概率可用于自动接受或人工复核。
2. **BGE 向量模型训练**：学习“哪些用户原声在业务上属于同一问题”，提高近邻召回、聚类纯度、难例分离和新问题发现能力。

两条线路不必同时训练。先建立未训练基线；优先训练 Laya 决策头。只有向量检索、聚类或相邻标签分离效果不达标时，才训练 BGE。

---

## 2. 你需要准备的三类数据

### 2.1 必需：标签体系表

每行一个标签，建议使用 CSV、Excel 或飞书表格，至少包含以下字段：

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| taxonomy_version | 是 | 标签体系版本 | voc_v1 |
| label_id | 是 | 稳定机器 ID，改名时不要更换 | L3_FALSE_DELIVERY |
| parent_id | 一级否，其余是 | 父标签 ID | L2_MISSING |
| level | 是 | 1、2、3 | 3 |
| label_name | 是 | 标签名称 | 显示送达但未收到 |
| definition | 是 | 明确的判定条件 | 状态已完成但用户明确未收到 |
| include | 是 | 属于该标签的表现，多个用换行或分隔符 | 提前点送达；餐品未见 |
| exclude | 是 | 容易混淆但不属于的表现 | 普通配送超时 |
| positive_examples | 是 | 真实正例，建议至少 3 条 | 人和餐都没看见 |
| negative_examples | 是 | 相邻标签真实反例，建议至少 3 条 | 骑手一直没动 |
| business_action | 是 | 命中后可采取的动作 | 进入送达真实性核查 |
| critical_label | 建议 | 是否为高风险/高价值标签 | true |
| status | 是 | active、observe、deprecated | active |

要求：

- 一级标签的 `parent_id` 为空；二、三级标签的父节点必须存在。
- 同级标签必须可区分；不能同时出现定义几乎相同的标签。
- 每个叶子标签必须有正例、反例和业务动作。
- 建议每个父节点不超过 20 个直接子标签；超过时优先重构层级。

### 2.2 必需：用户原声金标表

一行表示一个可独立判定的问题点。如果一条原声包含多个问题，拆成多行，并保留相同 `record_id`、不同 `issue_id`。

| 字段 | 必填 | 说明 |
|---|---|---|
| record_id | 是 | 原始记录稳定 ID，必须按文本保存，不能被 Excel 改成科学计数法 |
| issue_id | 是 | 同一原声中的问题点编号，如 1、2 |
| raw_text | 是 | 完整用户原声 |
| evidence_span | 是 | 支撑标签的连续原文片段，必须能在 raw_text 中原样找到 |
| label_l1_id | 是 | 一级标签 ID |
| label_l2_id | 视体系 | 二级标签 ID |
| label_l3_id | 视体系 | 三级标签 ID |
| source | 建议 | 渠道，如客服工单、评价、热线 |
| event_time | 建议 | 原声发生时间，用于时间外测试与漂移分析 |
| group_id | 强烈建议 | 会话、订单或用户级分组 ID，防止同源文本跨训练集泄漏 |
| annotator_1 | 建议 | 第一位标注者结果或姓名 |
| annotator_2 | 边界样本必填 | 第二位标注者结果或姓名 |
| adjudicated | 是 | 是否完成冲突仲裁 |
| annotation_confidence | 建议 | high、medium、low |
| notes | 可选 | 边界说明、业务背景 |

硬约束：

- 原始文本不得因为”方便训练”而改写；清洗只允许空格和编码处理。
- `evidence_span` 必须是 `raw_text` 的连续原文。
- 不能用执行 AI 的伪标签充当独立测试集。
- 同一 `group_id` 的数据只能进入一个数据分区。
- 重复和近重复原声不能跨训练、校准和测试集。

### 2.3 建议：未标注原声池

用于发现长尾问题、构造 BGE 训练对、评估聚类稳定性和检查数据漂移。

至少包含：

- `record_id`
- `raw_text`
- `source`
- `event_time`
- `group_id`（如有）

建议准备最近 1—3 个月、覆盖主要渠道和用户群的真实分布数据。未标注数据不直接用于 Laya 监督训练。

## 3. 建议数据规模

以下是启动标准，不是越多越好；边界质量、难例比例和测试集独立性比单纯数量更重要。

### 3.1 Laya 金标规模

| 阶段 | 每个叶子标签建议样本 | 用途 |
|---|---:|---|
| 可行性试验 | 50—100 条 | 判断标签定义和模型路线是否成立，不用于正式上线承诺 |
| 首版正式训练 | 150—300 条 | 训练决策头、阈值校准、形成基本稳定的每类指标 |
| 高频或高风险标签 | 300—500 条 | 提高边界覆盖和召回率 |
| 稀有但关键标签 | 尽量达到 80—150 条 | 不因占比低而合并；优先定向补样本和难例 |

如果有 20 个叶子标签，建议准备约 3,000—6,000 条人工确认的问题点。标签极不均衡时，不要靠复制少数类样本凑数，应定向补充真实样本。

每个叶子标签还应至少包含：

- 20—30 条与相邻标签容易混淆的边界样本；
- 10—20 条不同口语、错别字、省略表达或反讽表达；
- 真实渠道和时间段的多样性；
- 高风险标签的典型与隐晦表达。

### 3.2 BGE 训练规模

你不需要手工制造正负样本对。只要提供上述金标表，训练程序可自动生成：

- **正样本对**：同一叶子标签、不同原声；
- **普通负样本**：不同一级标签；
- **难负样本**：同一父节点下不同叶子标签，或基础 BGE 检索出的高相似错类样本。

建议规模：

- 最低试验：5,000 个训练对；
- 推荐首版：20,000—50,000 个训练对；
- 每个 anchor 建议 1—2 个正样本、2—4 个难负样本；
- 独立保留检索验证集和聚类验证集，不参与生成训练对。

## 4. 标注流程与质量控制

### 4.1 标注前

1. 冻结标签体系版本，例如 `voc_v1`。
2. 完成每个标签的定义、包含、不包含、正例、反例和业务动作。
3. 先做 100—200 条试标，集中暴露标签重叠、层级错误和无法覆盖的问题。
4. 修订标签树后再开始大批量标注，避免中途大规模返工。

### 4.2 正式标注

- 普通清晰样本可单人标注并抽检。
- 至少 10%—20% 的样本双人独立标注。
- 所有边界样本、低频高风险标签和多人意见不一致样本必须双标。
- 冲突样本由业务专家仲裁，并把判定依据补回标签定义卡。

### 4.3 建议标注质量门

- 三级完整路径一致率建议达到 85% 以上；
- 一级标签一致率建议达到 95% 以上；
- Cohen's Kappa 建议达到 0.80 以上；
- 未仲裁样本、低置信标注和标签定义不一致样本不得进入训练集。

以上是建议启动线；最终门槛可根据业务风险调整。

## 5. 数据切分方案

推荐按 `group_id` 和时间进行分组切分，禁止简单逐行随机切分。

| 分区 | 比例 | 用途 |
|---|---:|---|
| train | 70% | 更新模型参数 |
| validation | 10% | 选择训练轮数、学习率和是否过拟合 |
| calibration | 10% | 拟合温度和自动接受/拒识阈值 |
| test | 10% | 最终一次性验收，不参与任何训练或调参 |

切分要求：

- 同一用户、会话、订单或重复模板不得跨分区。
- 测试集优先采用较新的时间窗口，检验真实泛化与漂移。
- 每个正式标签在 validation、calibration、test 中尽量各有 20—30 条；达不到时应合并评估周期，而不是给出不稳定的单类指标。
- 高风险标签必须在 test 中保留足量样本，不得因比例低被随机切没。

## 6. 正式训练顺序

### 阶段 A：冻结标签与数据审计

输出：

- 标签树校验报告；
- 标签数量与样本分布；
- 重复/近重复、泄漏、缺失、未仲裁和证据不匹配清单；
- 训练可用样本数与缺口建议。

阻断条件：标签树结构错误、叶子标签没有训练样本、测试集泄漏、未仲裁数据混入。

### 阶段 B：建立基线

不训练模型，先测：

- 基础 Laya 的一级/二级/三级 Macro-F1、每类召回率、ECE 和拒识率；
- 基础 BGE 的 Recall@K、同标签近邻纯度、难负样本排序和聚类稳定性；
- 当前相似度阈值敏感性。

基线决定后续是否真的需要训练 BGE，以及 Laya 只训决策头是否足够。

### 阶段 C：Laya 决策头训练（首选）

本机推荐配置：

- 冻结 encoder；
- batch size 4 起步；
- 2—5 epochs；
- 学习率以 `2e-5` 为起点；
- 每轮验证，保留最佳 Macro-F1 checkpoint；
- 梯度裁剪 1.0；
- 训练结束后在 calibration 集拟合温度。

目的：以较低资源成本学习标签判定边界。若效果达到门槛，停止，不训练 Laya 全参数。

### 阶段 D：BGE 训练（按需）

仅当以下任一情况出现时执行：

- 同标签 Recall@10 或近邻纯度明显不足；
- 相邻标签难负样本经常排在正确样本之前；
- 聚类对阈值非常敏感，或大簇长期混杂；
- 新问题发现依赖业务术语，而通用 BGE 无法正确聚合。

训练方式：对比学习，同标签正样本 + 同父节点难负样本。训练后重新生成全量向量，并重新选择相似度阈值；旧阈值不能直接沿用。

本机建议：batch size 8—16 起步，显存/统一内存不足时降低 batch 并使用梯度累积。

### 阶段 E：Laya 部分/全参数训练（最后手段）

只有决策头训练仍无法学会业务表达时才考虑。当前训练脚本支持冻结编码器或全参数训练；正式全参数训练前需要增加梯度累积、早停和最佳 checkpoint 保存。

本机建议：

- batch size 1—2；
- 学习率 `1e-6`—`5e-6`；
- 1—3 epochs；
- 先短跑 200—500 个 step 监控内存、温度和吞吐；
- MacBook Air 无风扇，长训练可能降频，必要时转 Merlin GPU。

### 阶段 F：概率校准与拒识阈值

在独立 calibration 集上：

1. 拟合温度参数；
2. 比较不同 Top1 置信度和 Top1-Top2 margin；
3. 在自动覆盖率与错误率之间选取阈值；
4. 对高风险标签设置单独的最低召回或更严格拒识规则；
5. 固化模型版本、标签版本和阈值版本。

## 7. 建议验收门槛

以下作为首版建议，训练前可按业务风险调整：

| 指标 | 建议门槛 |
|---|---:|
| 一级标签 Macro-F1 | ≥ 0.90 |
| 二级标签 Macro-F1 | ≥ 0.85 |
| 三级标签 Macro-F1 | ≥ 0.80 |
| 高风险标签 Recall | ≥ 0.90 |
| ECE | ≤ 0.08 |
| 已接受样本准确率 | ≥ 0.90 |
| 人工复核率 | 10%—25%，并确保错误率可控 |
| BGE Recall@10 | ≥ 0.90 |
| 同标签近邻纯度 | ≥ 0.80 |

不能只看总体 Accuracy。必须输出每个标签的 Precision、Recall、F1、样本数、混淆对象，以及拒识前后的覆盖率和准确率。

发布阻断条件：

- 任一高风险标签测试样本不足；
- 高风险召回不达标；
- 测试集参与了训练或阈值选择；
- 新模型总体指标提高但关键标签明显退化；
- 温度校准后概率仍严重失真；
- 新 checkpoint 无法被 `laya.load()` 重新加载并复现结果。

## 8. 你的电脑可执行范围

当前设备已实测：Apple M5、16GB 统一内存、PyTorch MPS 可用。

- Laya 约 3.22 亿参数；完整优化器 step 已在 MPS 成功，驱动内存约 6.44GB。
- Laya 决策头约 1,500 万参数；适合本机正式训练。
- BGE-small-zh-v1.5 约 2,400 万参数；MPS 完整优化器 step 已成功，驱动内存约 1.09GB。
- 本机适合 Laya 决策头训练、温度校准和 BGE-small 全参数训练。
- Laya 全参数训练技术上可行，但速度慢、长时间可能因无风扇降频；数据较大时优先转 Merlin GPU。

正式训练前先对 200—500 个 step 做速度、内存和温度基准，再推算完整训练时长，不提前给不可靠的固定耗时承诺。

## 9. 训练交付物

完成一次正式训练后应交付：

1. 数据审计报告与被剔除样本清单；
2. 冻结标签体系及版本变更说明；
3. train/validation/calibration/test 的不可变清单；
4. 基础模型与训练后模型对比报告；
5. Laya checkpoint、训练配置、温度和拒识阈值；
6. 如训练 BGE：BGE checkpoint、相似度阈值和近邻/聚类评估；
7. 每标签指标、混淆矩阵、错误案例和高风险召回；
8. 可复现运行清单；
9. 固定 6 张子表的飞书结果表。

## 10. 你现在准备数据时只需做这些

1. 整理并冻结标签体系表。
2. 按“一条独立问题点一行”整理人工金标表。
3. 保留 `record_id`、`group_id`、渠道和时间，不要提前随机拆分。
4. 对至少 10%—20% 样本做双标；边界和高风险样本全部双标。
5. 给每个叶子标签准备真实正例、相邻标签反例和边界样本。
6. 另备一份未标注原声池；不需要手工制作 BGE 正负样本对。
7. 交付前自行检查未仲裁样本和重复数据。

你把标签体系表、金标表和未标注原声池交给我后，我先做数据审计与基线评估，再决定只训练 Laya 决策头，还是同时训练 BGE；不会未经评估直接全量训练。
